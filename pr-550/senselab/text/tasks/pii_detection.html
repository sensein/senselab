336    subprocess-backed detection.

339    call (one entry per input index) rather than one subprocess per input — the venv's
340    model loads (~5-10s each for Presidio/GLiNER) dominate cost, so batching a whole
341    sequence avoids paying that repeatedly.
342
343    Args:
344        inputs: A single ``str``, a single ``ScriptLine``, or a sequence of either
345            (may be mixed). A ``ScriptLine`` with no text anywhere in its tree (e.g. a
346            diarization line carrying only a ``speaker`` label) flattens to ``""`` and
347            is treated exactly like an empty string input — a documented empty result,
348            not an error.

350            both. An empty list (``[]``) is the caller explicitly disabling detection:
351            no subprocess is spawned, every report gets ``detector_used=None`` and an
352            explicit ``"pii_disabled"`` failure note — the LLM-judge-shaped case: this
353            module ships no LLM judge, and there is deliberately no default-on path
354            that would require one.
355        presidio_score_threshold: Presidio entities below this score are dropped at
356            extraction time. 0.4 is permissive enough to catch standard phone-number
357            formats; cross-detector corroboration still gates the boolean flag for
358            borderline scores.
359        gliner_model: HuggingFace model id for GLiNER. ``None`` uses the subprocess
360            module's default (``nvidia/gliner-pii``). Ignored when ``"gliner"`` is
361            excluded from ``detectors``.
362        gliner_labels: Labels passed to GLiNER's ``predict_entities``. ``None`` uses
363            the subprocess module's curated HIPAA-18 default set.
364        gliner_threshold: Drop GLiNER predictions below this score.
365        require_cross_source_corroboration: When ``True`` (default) and both detectors
366            ran, only flip ``contains_pii`` to ``True`` for a ``(category,
367            normalized_text)`` pair that both Presidio and GLiNER independently
368            flagged. A caller corroborating across multiple ASR transcripts of the same
369            recording applies the same rationale one layer up (see the ``audio_analysis``
370            workflow's per-pass PII adapter); this generalizes it to cross-detector
371            agreement since a standalone input has exactly one transcript to corroborate.
372            When only one detector ran, any single detection counts (corroboration cannot
373            apply with one witness).

377        list of ``PiiReport``, same length and order as ``inputs``, when it is a

380        subprocess failure, or no detector loaded) — distinct from ``detection_confidence
381        == 0.0``, which means detection ran and found nothing.

Scan a string or ScriptLine (or a sequence of either) for PII.

Standalone entry point: no dependency on any audio-workflow concept (a run "pass", a per-pass tag, an ASR-model ensemble). str and ScriptLine are two entry shapes over one implementation — a ScriptLine is flattened to text via flatten_script_line() first, then both shapes go through the same subprocess-backed detection.

Every non-empty input is sent to detect_pii_via_subprocess in a single batched call (one entry per input index) rather than one subprocess per input — the venv's model loads (~5-10s each for Presidio/GLiNER) dominate cost, so batching a whole sequence avoids paying that repeatedly.

Arguments:
  • inputs: A single str, a single ScriptLine, or a sequence of either (may be mixed). A ScriptLine with no text anywhere in its tree (e.g. a diarization line carrying only a speaker label) flattens to "" and is treated exactly like an empty string input — a documented empty result, not an error.
  • detectors: Subset of {"presidio", "gliner"} to run. None (default) runs both. An empty list ([]) is the caller explicitly disabling detection: no subprocess is spawned, every report gets detector_used=None and an explicit "pii_disabled" failure note — the LLM-judge-shaped case: this module ships no LLM judge, and there is deliberately no default-on path that would require one.
  • presidio_score_threshold: Presidio entities below this score are dropped at extraction time. 0.4 is permissive enough to catch standard phone-number formats; cross-detector corroboration still gates the boolean flag for borderline scores.
  • gliner_model: HuggingFace model id for GLiNER. None uses the subprocess module's default (nvidia/gliner-pii). Ignored when "gliner" is excluded from detectors.
  • gliner_labels: Labels passed to GLiNER's predict_entities. None uses the subprocess module's curated HIPAA-18 default set.
  • gliner_threshold: Drop GLiNER predictions below this score.
  • require_cross_source_corroboration: When True (default) and both detectors ran, only flip contains_pii to True for a (category, normalized_text) pair that both Presidio and GLiNER independently flagged. A caller corroborating across multiple ASR transcripts of the same recording applies the same rationale one layer up (see the audio_analysis workflow's per-pass PII adapter); this generalizes it to cross-detector agreement since a standalone input has exactly one transcript to corroborate. When only one detector ran, any single detection counts (corroboration cannot apply with one witness).
Returns:

A single PiiReport when inputs is a scalar str/ScriptLine; a list of PiiReport, same length and order as inputs, when it is a sequence. detector_used=None and detection_confidence=None together mean detection did not actually run for that input (disabled, empty input, subprocess failure, or no detector loaded) — distinct from detection_confidence == 0.0, which means detection ran and found nothing.

def flatten_script_line(line: senselab.utils.data_structures.script_line.ScriptLine) -> str: 
114def flatten_script_line(line: ScriptLine) -> str:
115    """Join a ScriptLine's text with its nested chunks', depth-first.
116
117    Backends differ in where they put the words: Whisper returns segment text
118    plus word-level ``chunks``, a forced aligner returns segment-level lines with
119    word-level chunks nested underneath, and a diarization line carries a speaker
120    and no text at all. Scanning only ``text`` would make PII coverage silently
121    depend on which backend produced the transcript, so the whole tree is
122    flattened instead.
123
124    Args:
125        line: The ``ScriptLine`` to flatten. Its own ``text`` (if any) comes
126            first, followed by each child's flattened text in order.
127
128    Returns:
129        The concatenated, whitespace-normalized text. Empty string when the
130        line and all its descendants carry no text (e.g. a diarization line
131        with only a ``speaker`` label) — this is a normal, documented result,
132        not an error.
133    """
134    parts: list[str] = []
135    own = (line.text or "").strip()
136    if own:
137        parts.append(own)
138    for child in line.chunks or []:
139        nested = flatten_script_line(child)
140        if nested:
141            parts.append(nested)
142    return " ".join(parts)
