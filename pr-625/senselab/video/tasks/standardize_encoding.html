senselab.video.tasks.standardize_encoding

Standardize a video's encoding

Task overview

Re-encode (or, when it already conforms, remux) a video file into one fixed, seek-friendly H.264/AAC encoding with a predictable GOP, and return the output path together with a provenance record. Every target (resolution, frame rate, audio rate, channels) defaults to "keep the source", so the default call produces the archival standard; a model name or explicit targets produce a model-ready input on the fly.

Adapted from the BBQS encoding-helper "recommended" encode (MIT licence): H.264 High, -preset slow -crf 23, yuv420p, AAC, +faststart, metadata stripped.

Choice encoding-helper here why
Frame rate assumes ~30 fps native (-fps_mode passthrough, no -r) timestamps and frame counts are evidence; resample only on request
B-frames High-profile default none (bframes=0) decode order equals display order; a cut at a keyframe is exact
GOP keyint=30 round(fps) frames, min-keyint equal, scene-cut off exactly one second of the native rate, keyframes at indices 0, K, 2K, ...
Audio AAC 128k rate and channels kept; AAC copied, else 192 kbit/s no resampling unless a target asks for it
Rotation n/a applied (upright pixels, no display matrix) models ignore the matrix

Usage

from senselab.video.tasks.standardize_encoding import standardize_video_encoding

# archival standard: everything native
result = standardize_video_encoding("in.mov", "out.mp4")
result.ok, result.provenance["mode"], result.provenance["check"]

# on the fly, for a model: 32-pixel grid, fast preset, GPU if present, cached by content
result = standardize_video_encoding("in.mov", model="qwen3-vl", profile="transient", backend="auto", cache_dir="/scratch/cache")

# explicit targets
standardize_video_encoding("in.mov", "out.mp4", resolution=(640, 640), resolution_mode="pad", fps=10, audio_rate=16000, audio_channels=1)

ffmpeg and ffprobe (with libx264; h264_nvenc for the GPU backend) are found on PATH or passed as ffmpeg=/ffprobe=. scripts/install-ffmpeg.sh installs a build.

Targets, profiles, backends

  • resolution: None keeps the size (odd sizes are cropped to even); an int caps the longest side (never upscales); (W, H) with resolution_mode fit (inside, aspect kept, never upscaled), pad (fit then black bars to exactly W x H), crop (cover then centre-crop) or stretch. resolution_multiple floors sizes to a patch grid (28 for Qwen2.5-VL, 32 for Qwen3-VL).
  • fps: None keeps the source timestamps. A number resamples to a constant rate by dropping or duplicating the nearest frame (fps_method="drop-dup"); the GOP becomes round(fps). For a VFR source without a target the GOP is round(average fps) frames, which is not exactly one second everywhere; the provenance records vfr.
  • audio_rate / audio_channels: None keeps them; otherwise the first audio stream is resampled/remixed to AAC.
  • profile: archival (-preset slow) or transient (-preset veryfast, NVENC p4). preset= overrides.
  • backend: libx264 (reference, bit-reproducible for a given ffmpeg build and thread count), h264_nvenc (NVDEC decode, NVENC encode with -cq; its output differs from x264 at the same CRF, so quality should be checked before archival use), or auto. The backend is recorded in the provenance.

Fast path and cache

A source that is already H.264 yuv420p, upright, B-frame free, even-sized and keyframed exactly every round(fps) frames is remuxed (video stream copied, metadata stripped, +faststart): mode="remux", or "audio-only" when just the audio needs encoding. Remuxing keeps the source's own quality and bitrate. Long-GOP camera files never match and are re-encoded. With cache_dir, results are content addressed by sha256(source sha256, resolved parameters, ffmpeg version); a hit returns without encoding. Entries are never evicted.

Provenance

provenance holds: mode, backend, profile, source (size, sha256, xxh3 when installed), output (size, hashes, ratio), avg_frame_rate, r_frame_rate, fps, vfr, duration, frames_decoded, geometry, rotation, audio, settings (every encode parameter, including the targets), ffmpeg_version, timings, cache, and check: the output is decoded again and tested for frame count, timestamps (1 ms), keyframes exactly at multiples of the GOP, no B-frames, geometry and audio rate, channels and duration (50 ms). ok is true when all pass.

Model input specs

MODEL_INPUT_SPECS declares, per model, whether it needs specific dimensions, the patch multiple, preferred frame rate and audio format, and the source of each claim; verified=False marks entries not read from a processor config. model="name" derives the targets; explicit arguments win. Frame sampling stays with each model's processor.

Limits

Only the first video and first audio stream are kept (other streams, chapters and metadata are dropped). 10-bit and full-range sources are converted to 8-bit limited-range yuv420p. No VMAF is computed here (the ffmpeg build may lack libvmaf).

530
531    **Contract (every profile and target).** H.264 High, ``yuv420p``, no B-frames, scene-cut off, keyframes at
532    frame indices ``0, K, 2K, ...`` with ``K = round(fps)`` (fps = the target when set, else the source's average),
533    presentation timestamps and frame count of the source kept (``-fps_mode passthrough``) unless ``fps`` is set,
534    first audio stream kept, ``+faststart``, all metadata stripped. Rotation metadata is applied (upright
535    pixels, no display matrix in the output). Only the first video and first audio streams are kept.
536
537    **Targets** (each ``None`` = keep the source). ``resolution``: an ``int`` (longest side at most that many
538    pixels, never upscaled) or ``(W, H)`` with ``resolution_mode`` ``fit | pad | crop | stretch`` (see
539    ``target_dims``); dimensions are floored to ``resolution_multiple`` (default 2, which yuv420p needs; use 14/16/28/32
540    for patch-grid models). ``fps``: resample to a constant rate with ``fps_method="drop-dup"`` (nearest source frame
541    for each output tick, ffmpeg's ``fps`` filter), the GOP becoming ``round(fps)``. ``audio_rate`` /
542    ``audio_channels``: resample / remix the audio to AAC. ``model``: a ``ModelInputSpec`` or a registered name;
543    it supplies the targets above (explicit arguments win).
544
545    **Profiles.** ``archival`` is ``-preset slow`` (the dataset-wide standard with every target ``None``);
546    ``transient`` is ``-preset veryfast`` (``p4`` on NVENC) for on-the-fly preparation. ``preset`` overrides.
547    ``backend`` is ``libx264`` (CPU, the reproducible reference), ``h264_nvenc`` (GPU encode, NVDEC decode; ``-cq``
548    quality, output differs from x264 at the same CRF) or ``auto`` (NVENC when a test encode works, else libx264).
549    The backend used is recorded in the provenance.
550
551    **Fast path.** With ``allow_copy`` and no resolution/fps change, a source that is already H.264 ``yuv420p``,
552    upright, B-frame free, even-sized and keyframed exactly every ``K`` frames has its video stream copied
553    (``mode="remux"``; ``"audio-only"`` when only the audio needs encoding); the source's own quality and bitrate
554    are kept. Otherwise ``mode="reencode"``. Sources that never match (long-GOP camera files) are re-encoded.

Re-encode video to the standard encoding and return the output path with its provenance.

Contract (every profile and target). H.264 High, yuv420p, no B-frames, scene-cut off, keyframes at frame indices 0, K, 2K, ... with K = round(fps) (fps = the target when set, else the source's average), presentation timestamps and frame count of the source kept (-fps_mode passthrough) unless fps is set, first audio stream kept, +faststart, all metadata stripped. Rotation metadata is applied (upright pixels, no display matrix in the output). Only the first video and first audio streams are kept.

Targets (each None = keep the source). resolution: an int (longest side at most that many pixels, never upscaled) or (W, H) with resolution_mode fit | pad | crop | stretch (see target_dims); dimensions are floored to resolution_multiple (default 2, which yuv420p needs; use 14/16/28/32 for patch-grid models). fps: resample to a constant rate with fps_method="drop-dup" (nearest source frame for each output tick, ffmpeg's fps filter), the GOP becoming round(fps). audio_rate / audio_channels: resample / remix the audio to AAC. model: a ModelInputSpec or a registered name; it supplies the targets above (explicit arguments win).

Profiles. archival is -preset slow (the dataset-wide standard with every target None); transient is -preset veryfast (p4 on NVENC) for on-the-fly preparation. preset overrides. backend is libx264 (CPU, the reproducible reference), h264_nvenc (GPU encode, NVDEC decode; -cq quality, output differs from x264 at the same CRF) or auto (NVENC when a test encode works, else libx264). The backend used is recorded in the provenance.

Fast path. With allow_copy and no resolution/fps change, a source that is already H.264 yuv420p, upright, B-frame free, even-sized and keyframed exactly every K frames has its video stream copied (mode="remux"; "audio-only" when only the audio needs encoding); the source's own quality and bitrate are kept. Otherwise mode="reencode". Sources that never match (long-GOP camera files) are re-encoded.

Cache. With cache_dir the output is stored as <dir>/<key[:2]>/<key>.mp4 (+ .json) where key = sha256(source sha256, resolved parameters, ffmpeg version); a repeated request returns it without encoding (provenance["cache"]["hit"]).
