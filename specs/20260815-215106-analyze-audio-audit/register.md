## Severity (assigned in this task; not in any input file)

None of the three input documents (`deduped.md`, the two verdict files) carries a severity
field, so this register defines one rubric and applies it uniformly:

- **high** — the defect changes a value written into a `final/*.json`/`final/*.parquet`
  deliverable, or a headline run-level number (`combined_uncertainty`, `run_state`,
  `transcript.wer`), with no config override and no mitigation elsewhere in the pipeline.
- **medium** — a real, demonstrated/latent defect, but with a narrower blast radius: gated
  behind an unusual precondition (e.g. multiple diarizer crashes), currently unwired into any
  production call path, or affecting internal budget/priority accounting rather than a
  published value directly.
- **low** — no data-value impact: a prose-layer (`stale-or-false`) docstring mismatch, a
  promotion-candidate (placement/reuse opportunity, not a functional defect), or a
  developer-environment trap (`types.py` shadowing) that does not trigger inside the packaged
  entry points the triage graph would actually call.

## `graph_implication` (judged against the planned triage workflow)

The planned triage workflow produces, per audio file: a **human-review flag**, a **transcript**,
a **speaker count**, whether **PII** exists, **recording quality**, whether the recording
**matches its expected task**, and what to **trim**. For every `demonstrated`/`verified-latent`
row:

- **consumed** — the defect sits in a value one of those seven outputs reads (directly, or one
  hop upstream through a value that feeds it).
- **routed-around** — the defective code exists but is not on any path the seven outputs
  currently read (e.g. unwired into production, or shapes internal search priority rather than
  a published value) — the graph can ignore it today, at the cost of it silently reactivating if
  someone wires the dead path in later.
- **irrelevant** — no defect chain reaches any of the seven outputs at all (prose-only claims,
  promotion-candidates, dev-environment traps).

The 130 `## Ungated classification` entries are marked `irrelevant` in bulk (see that section) —
a classification label about where a comment belongs is not a runtime signal the graph could
consume or avoid in the first place.

## Statistical-review verdicts on existing findings

`statistical-review.md` (a Bayesian statistician's pass, reading the uncertainty arithmetic rather
than auditing the software) rendered verdicts on five existing rows. Each row above is annotated
in place with a bracketed pointer to this section; this section carries the reasoning the bracket
points at, so it exists once rather than being repeated in five `defect` cells.

- **F-146** (`binding_agreement=0.0` when `eligible==0`) — **severity reduced from medium to
  low**. It is the same defect as F-147 and F-186 (N10) — a plug-in statistic that cannot
  distinguish "nothing was measured" from "a confident zero" — and is fixed by the same one-line
  change (report `None`, carry `n_eligible`) those two already require. Tracking it as an
  independent medium-severity item double-counts one fix as three findings' worth of severity.
  `graph_implication` stays `routed-around`: still unwired into any production call path.
- **F-147** (`speech_presence_confidence = k/n_present`) — **the register's implied fix is wrong,
  not merely incomplete.** Changing the denominator to `n_enrolled` looks like the obvious
  correction but is not: a diarizer crashing on hard audio is missing-not-at-random (MNAR) — the
  failure is caused by the same acoustic difficulty the statistic is trying to estimate — so
  neither `k/n_surviving` nor `k/n_enrolled` is estimable from the data actually available. The
  correct treatment has three parts (recorded in full on the F-147 row): carry both `n_observed`
  and `n_enrolled`, replace the plug-in proportion with a Jeffreys posterior, and publish the
  MNAR completion bracket `[k/N, (k+m)/N]` rather than a point estimate. The review also found the
  *same* defect one level down, uncaught by the original 176: `_binary_entropy(share)` at
  `speaker.py:648` is a plug-in entropy of an MLE, structurally `0.0` at `n=1` regardless of data
  — so even a corrected denominator does not fix the entropy column derived from it.
- **F-156** (`boundary_confidence` fabricates `0.5`) — **reframed**, not re-tiered. The original
  framing ("misnamed-statistic," implying a bad choice of fallback number) obscures that `0.5` is
  the *only* value on this `[0,1]` scale meaning "no information" — any other fallback constant
  would be equally wrong, just wrong against a different band of real measurements. The defect is
  structural (a fabricated value and a measured value share one field), not a magnitude to
  re-pick. Fix is `None` plus a `boundary_source` column recording provenance, not a different
  number.
- **F-158** (`priority = gain / cost`) — **raised from medium to high.** This is not a scaling
  defect (as "misnamed-statistic" implies) but a decision-theoretic one: `priority` is meant to be
  a value-of-information ratio, and VOI must be computed in one currency. `_mass_gain` (bounded
  doubt-seconds), `_n_candidates_gain` (a raw unbounded count), and `_u2_gain` (an arbitrary
  ×10-scaled product) are not merely unnormalised relative to each other — they are measured in
  different units entirely, so sorting them into one priority list is comparing seconds against
  a raw count against an arbitrarily-scaled product and calling the result a ranking.
- **F-148** (promote `statistics.py`) — **endorsed, with a precondition warning attached**, not a
  plain endorsement. These are the best-argued functions in the package, which is exactly why
  promoting them without a docstring precondition is a risk: a shared location invites reuse by
  future callers who will feed them the same pseudo-distributions `fuse.py:426` already does
  (`{"unsettled": v, "settled": 1-v}` over a doubt score, where "settled" is not an observable and
  can never be calibrated). Promotion should carry the precondition that inputs be predictive
  distributions over an observable outcome space, or the promotion exports F-179/F-186's defect to
  every future caller instead of containing it.

Also endorsed without qualification: **F-151, F-163** — both existing refutations are correct
(ISO 1996-2 minimum measurability genuinely backs `recorder_margin_db=3.0`; `max()`/union over two
classifiers are legitimate aggregators, not the claimed ladder). Nothing else in the original 176
is statistically wrong per the review — its findings outside these six rows are prose,
promotion-candidate, or lifespan-population claims the review does not weigh in on.

`remediation-config.md` ran one question — *does every value that gates a verdict, classification,

unfitted thresholds a defect-shaped sweep happened to also flag under a different name." A sweep
built to look for one specific shape of problem does not find every instance of a much broader
class it wasn't asked about, and this register should not be read as though it did.

`pii.py`, so a reader of this register alone could conclude PII verdicts are the one output the
