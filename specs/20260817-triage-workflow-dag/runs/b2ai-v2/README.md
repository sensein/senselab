# b2ai-v2 — the three-participant triage-v2 campaign

The runbook for screening three b2ai subjects through the v2 triage fold. Everything the run
decides that the packaged config leaves `null` is in `override.yaml`, with a `GUESS`-prefixed
derivation beside each value. Nothing here was fitted.

| | |
|---|---|
| base commit | `a5a1d6e4` |
| config | `senselab-triage/default` v1 + `override.yaml` |
| **`config_hash`** | **`1bb3b69061bb75ea`** |
| subjects | `17cee767` (28 files), `1f4ea26f` (47), `17578482` (37) — 112 recordings |

The hash is stamped into every artifact. If it is not `1bb3b69061bb75ea` in a run's
`summary.json` → `provenance.config_hash`, that run is not this campaign.

The hash binds to the base commit as well as the override: the packaged default gained
`report.format: pdf` after this campaign closed, so a re-run of the same override on a later base
hashes differently (`34ad76742d0208d6` at the two-page-report commit). That is a different config,
not a corrupted run — the check above identifies *this* campaign's artifacts, it does not forbid
later ones.

## What is in this directory

| file | what it is |
|---|---|
| `override.yaml` | the campaign config override — every null the graph reads, each an admitted guess |
| `make_hints.py` | the per-file hint generator, and the rules it applies |
| `hints/` | the 28 hint files for subject `17cee767`, generated by `make_hints.py --b2ai-28` |
| `make_enrollment.py` | phase 2: estimate one subject's target-speaker enrollment from their own speech files |

**`hints/` holds only subject `17cee767`.** The other two subjects' hints are not checked in
because their file listings are not in this repository — the v1 tables for them live only on the
cluster, and this work had no cluster access. `make_hints.py` is the deliverable for all three: it
derives every hint from the task token in the filename, so the job regenerates the other two
subjects' hints from the cluster's own listing in one command (below). `--selftest` proves the
rules reproduce the v1 table for all 28 files whose hints we do have.

## Running one file

```bash
uv run python scripts/triage_audio.py "$WAV" \
    --config specs/20260817-triage-workflow-dag/runs/b2ai-v2/override.yaml \
    --hint   "$HINTS/$(basename "${WAV%.wav}").json" \
    --out    "$SCRATCH/triage_b2ai_v2/$SUB/"
```

Layout under `--out/<stem>_<utc-timestamp>/`: `run/` (the provenance store and derivatives),
`summary/` (the report page and its JSON, written on every outcome), `released/` (only when REDACT
cleared a release).

## Generating the hints

For a subject whose files are on the cluster:

```bash
cd specs/20260817-triage-workflow-dag/runs/b2ai-v2
uv run python make_hints.py --selftest              # first: the rules still reproduce v1

SUB=sub-1f4ea26f-9764-4f89-a41a-66e248b9386f
uv run python make_hints.py \
    --dir "/orcd/data/satra/002/datasets/b2aivoice/post_3.0/v3.1/adult/bids_07_01_lang/$SUB/" \
    --out "$SCRATCH/triage_b2ai_v2/$SUB/hints/"
```

It writes one `<recording-stem>.json` per `.wav`, refuses a task token no rule claims (see below),
and refuses a hint whose tags are not keys of the override's `routing.hint_kind_map`. Check the
count against the expected 47 / 37 before launching anything.

A hint declares what the protocol asked for; it is never a measurement. **No
`targeted_speaker_count` is written anywhere** — the v2 fold reads nothing from it, and a number
nobody counted does not belong in a file the graph reads.

### The rules

| task token | `may_contain` | `speech_type` |
|---|---|---|
| trailing `Cough`, `Cough-2` | `cough`, `airway` | non-lexical |
| anything containing `Breath` | `breathe`, `airway` | non-lexical |
| `Diadochokinesis-buttercup` | `speech`, `voice` | non-lexical |
| other `Diadochokinesis-*` | `voice` | non-lexical |
| anything containing `vowel` | `sustained-vowel`, `phonation`, `voice` | non-lexical |
| `Maximum-phonation-time-*` | `sustained-vowel`, `phonation`, `voice` | non-lexical |
| `Glides-*`, `Loudness` | `phonation`, `voice` | non-lexical |
| `*Passage*`, `Reading*` | `read-speech`, `speech` | read |
| `Free-speech-*`, `Picture-description`, `Productive-Vocabulary*`, `Random-Item-Generation*`, `Word-color-Stroop*` | `speech` | elicited |
| `Story-recall`, `Cinderella-Story*` | `speech` | recall |

Order is load-bearing for the first two: **every** respiration file carries "cough" in the
protocol's own name (`Respiration-and-cough-Breath-1`), so the cough test is a *trailing* match and
runs before the breath test. A substring match here tags five breath files as coughs.

An unrecognised token is a **hard failure**, not an empty hint. An empty `may_contain` reads as "the
protocol declared nothing", which is itself a claim, and it forces no branch — so a silently
unhinted file would be screened with less evidence than it had. Extend `RULES` in `make_hints.py`,
or pass `--allow-unknown` deliberately (it writes `metadata.unmapped_task: true` and warns).

### The one rule that differs from the ledger's summary

The ledger's summary line groups `Glides / Loudness / MPT → [phonation, voice]`. The v1 hint table
that actually ran (`runs/b2ai-28/hints.json`) gives all three MPT files
`[sustained-vowel, phonation, voice]`. **The table governs and the rules follow it**, because
maximum phonation time *is* a sustained vowel task and because `--selftest` compares against the
table, not the summary. Under this campaign's `hint_kind_map` the difference changes no routing —
`sustained-vowel`, `phonation` and `voice` all map to the `voice` kind — but it changes what the
verdict records the protocol as having declared, which is the point of a hint.

## Pre-flight: check the detectors actually loaded

**Run this on one file per host before launching any array.** The v1 campaign withheld release on
7 of 28 files with `the store's pii scan is incomplete (required detectors were not attempted:
gliner, presidio, rules; no detector ran)`. A PII scan that never happened is indistinguishable in
the final table from a scan that found nothing, except that senselab correctly refuses to release
it — so an unloaded detector silently costs you every release decision in the batch.

Pick a file with **lexical content** (`Rainbow-Passage`, `Free-speech-1`): the scan runs over the
consensus transcript, so a non-lexical file legitimately produces no scan and tests nothing.

```bash
PREFLIGHT="$SCRATCH/triage_b2ai_v2/preflight"          # a dedicated, empty --out
uv run python scripts/triage_audio.py "$SUB_DIR/..._task-Rainbow-Passage.wav" \
    --config .../override.yaml --hint .../hints/..._task-Rainbow-Passage.json \
    --out "$PREFLIGHT"

uv run python - "$PREFLIGHT" <<'PY'
import json, pathlib, sys

run = max(pathlib.Path(sys.argv[1]).glob("**/run/store.jsonl"), key=lambda p: p.stat().st_mtime)
scan = next(
    (a for line in run.open() for a in [json.loads(line).get("attributes") or {}] if a.get("name") == "pii_scan"),
    None,
)
assert scan is not None, "PREFLIGHT FAILED: no pii_scan in the store -- pick a file with words"
print("scanned_by:", scan["scanned_by"], "failed:", scan["failed"], "missing:", scan["missing"])
assert scan["scanned_by"], "PREFLIGHT FAILED: no detector ran; do not launch the array"
assert not scan["failed"] and not scan["missing"], "PREFLIGHT FAILED: incomplete detector set"
print("PREFLIGHT OK")
PY
```

This snippet is exactly the one run against the second smoke below, where it printed
`scanned_by: ['gliner', 'presidio', 'rules'] failed: [] missing: []` / `PREFLIGHT OK`. Its
`assert scan is not None` is not decoration: pointed at a non-lexical run it fires, which is the
"pick a file with words" case.

Expected: `scanned_by: ['gliner', 'presidio', 'rules'] failed: [] missing: []` — the three
`pii.required_detectors` the packaged config names. Anything less and the array will withhold every
release for scan-incompleteness. `gliner` is the one that needs a model download; a cold cache on a
compute node with no network is the usual cause.

## Phase 1: the unenrolled screening pass

Run all 112 files with `--config` and `--hint` and no `--enrollment`. `speech.target_match_cosine`
is read only when an enrollment is supplied, so phase 1 never touches it; SPEECH reports its
diarized speaker count without deciding which speaker is the subject.

Phase 1 is what tells you whether a subject's files are worth enrolling from at all: a subject whose
files diarize to one speaker throughout is a clean enrollment source, and one whose files carry a
clinician's voice is not.

## Phase 2: enrollment

An enrollment is one subject's target-speaker vector, estimated across that subject's own
recordings. `make_enrollment.py` is a thin driver over
`senselab.audio.tasks.speaker_embeddings.estimate_speaker_embedding_from_audios`, which does the
work — windows each file, embeds every window with ECAPA, pools them, and describes the resulting
distribution.

```bash
SUB=sub-17cee767-1864-457a-b2ec-446a058a81f8
uv run python specs/20260817-triage-workflow-dag/runs/b2ai-v2/make_enrollment.py \
    --subject "$SUB" \
    --dir "/orcd/data/satra/002/datasets/b2aivoice/post_3.0/v3.1/adult/bids_07_01_lang/$SUB/" \
    --created-at "2026-08-25T00:00:00Z" \
    --out "$SCRATCH/triage_b2ai_v2/enrollment/$SUB.yaml"
```

Then re-run that subject's files with `--enrollment "$SCRATCH/.../enrollment/$SUB.yaml"` added to
the phase-1 command line. Everything else, including `--config`, stays identical, so the phase-1 and
phase-2 verdicts share one `config_hash` and are directly comparable.

### The source policy: speech files only

The `--dir` above scans the whole subject directory, and the estimate is nonetheless made over that
subject's **speech** recordings alone. This is the owner's ruling of 2026-08-25, verbatim:

> enrollment should skip breathing/cough/airway files and focus on speech, as we are generally
> trying to remove other speakers from such recordings.

**The rule as implemented.** A candidate is an enrollment source exactly when its task token
resolves — through `make_hints.task_token` and `make_hints.resolve`, the same rules that write the
hints, imported rather than re-expressed — to a rule whose `metadata.speech_type` is `read`,
`elicited` or `recall`. That is: Rainbow/Caterpillar and any other `-Passage`, `Reading-*`,
Harvard-Sentences, Cape-V-sentences, Free-speech, Picture-description, Productive-Vocabulary,
Random-Item-Generation, Word-color-Stroop, Story-recall and Cinderella-Story. Everything whose
`speech_type` is `non-lexical` is excluded, which is both limbs of the ruling:

- **airway** — every `Respiration-and-cough-*` file, cough and breath alike;
- **non-lexical voice** — Prolonged-vowel, Maximum-phonation-time, Glides, Loudness and
  Diadochokinesis.

`Diadochokinesis-*-buttercup` is the one token where the two hint fields disagree: its `may_contain`
carries `speech` (the syllable string is lexical) while its `speech_type` is `non-lexical`. The
**`speech_type` governs the source policy**, so buttercup is excluded with the rest of DDK — a
centroid meant to separate the target's connected speech from another talker's is not helped by
three seconds of repeated syllables. On the two task inventories `make_hints` pins, the policy
selects 6 of the v1 subject's 28 files and 32 of the (v2) subject's 47.

**Why.** Enrolling over ALL of a subject's files pulls the ECAPA centroid toward material that is
not speech at all. Measured on this corpus: a HardCough file scores cosine **−0.045** against its
own subject's centroid; leave-one-file-out medians land at **0.51–0.64**, straddling the guessed 0.5
cut in both directions; target attribution at that cut is **53%**, which is a coin toss. The centroid
was being asked to represent two different things at once, and it represented neither.

**It is policy, not an option.** There is no flag to enrol over everything, because there is no
measurement that would justify one. `--exclude` still drops a named basename from the candidates
before the policy runs — it curates within speech, it does not re-admit non-speech.

**A subject with no speech file is refused**, with the exclusion counts in the message, rather than
enrolled from whatever airway files the session happens to hold. A filename carrying no `task-`
element is excluded as `unclassified` and named in the report; it is never enrolled from on the
guess that it might be speech.

**Seeing the selection without spending a model.** `--list-sources` prints the partition — every
selected file, every exclusion with its category, and the counts — and exits before anything is
loaded or embedded. `--selftest` checks the policy against both pinned task inventories, the
`(v2)`-protocol token variants, the unreadable-name case and the zero-speech refusal, and reaches no
audio at all.

```bash
uv run python .../make_enrollment.py --list-sources --dir ".../$SUB/"
uv run python .../make_enrollment.py --selftest
```

**Still owed:** the cut. `speech.target_match_cosine` is null and remains unfitted; the 53%
attribution above was measured against a *guessed* 0.5 on a *contaminated* centroid, so it is not
the number a speech-only centroid would give. Both the fit and the re-measurement are open in
`benchmarks/open.md`.

### Three other things that are not obvious

- **The model commit is pinned, and it has to be.** `SPEECH` passes
  `speech.enrollment_model.revision` straight into `Enrollment.refusal_against` as the probe commit
  — `speech.py:785`, no resolution of its own — and that method compares it for **equality** against
  the enrollment's `provenance.model_commit_sha`, which the estimator always records as a resolved
  40-hex sha. So a `revision: main` in the override refuses *every* enrollment on *every* file with
  "the enrollment was estimated at commit `<sha>` and the probe resolves to main", and phase 2
  quietly degrades into phase 1 plus a refusal. The override pins
  `speechbrain/spkrec-ecapa-voxceleb@0f99f2d0ebe89ac095bcc5903c4dd8f72b367286`, resolved on
  2026-08-25; `make_enrollment.py` reads that pin, estimates at it, and refuses to write a file
  whose commit disagrees. Re-pin with:

  ```bash
  uv run python -c "from senselab.utils.model_revision import resolve_revision; \
      print(resolve_revision('speechbrain/spkrec-ecapa-voxceleb', 'main'))"
  ```

- **Within the selected speech, the estimator reaches no verdict about its input.** A file that
  does not contain the target speaker is not an error there; it is a row in the returned per-file
  statistics. Read `provenance.extraction_failures`, `n_windows_dropped`, and the distribution's
  `leave_one_file_out_cos` and `cross_file` blocks before trusting the vector, and curate further
  with `--exclude`. `--reject-contamination` keeps only the dominant window group — a decision,
  recorded in `provenance.method` as `spherical_mean+dominant_cluster`.

- **`created_at` is not defaulted to "now".** Pass `--created-at` so the output is reproducible.

## Exit codes

As shipped by `scripts/triage_audio.py`:

| code | meaning |
|---|---|
| `0` | VERDICT concluded and no node raised |
| `1` | a node raised, or VERDICT never concluded. The verdict is still written and the run directory still holds everything the graph reached |
| `2` | the arguments could not be resolved — missing audio, invalid config, invalid hint, invalid enrollment. **Nothing was measured** |

The code reports whether the *graph ran*, never what it *concluded*: a `discard` verdict is a
successful run and exits `0`. An array job that treats `1` as fatal will discard partial evidence
that is on disk and worth reading; treat `2` as fatal and `1` as "collect and triage".

## Two config keys that are now unread

**`speech.hint_tags` and `voice.hint_tags` are unread as of the v2 fold.** Hints route through
`routing.hint_kind_map` alone (`routing.py:_map_tags`); nothing in the tree reads either key, and
the `hint_tags` that appears on a branch decision is a local variable holding the tags that map to
that kind, not this config value. This override deliberately does **not** set them — setting an
unread key would put a decision into `config_hash` that changes no behaviour. **Deleting both keys,
and the paragraph in the packaged `derivation` that explains them, is a cleanup candidate.**

## Corrections this campaign made to the final review's required-key list

Three, each of which would have failed the run or made part of it inert:

1. **`windows.{yamnet,ast,hear}.label_thresholds` may NOT stay null.** The review said they could.
   `preprocess.py:411` reads them through `config.require()`, which raises on null exactly as it
   does on a missing key, so all three window folds would have raised, no label lane would have
   rendered, and every acoustic evidence line would have read `unavailable` — making every kind
   uncertain on every file. The override sets `{}`, which is the declaration "no per-label
   override".
2. **`speech.enrollment_model` is a mapping, not a string, and its revision must be a resolved
   commit.** See "Phase 2" above.
3. **`routing.hint_kind_map` needs an `airway` entry.** The review's map omitted it. The v1 hint
   table tags every respiration and cough file with both the event tag and `airway`; unmapped, the
   tag most load-bearing for those files would have read as declared while forcing nothing. The map
   also carries the three `metadata.speech_type` values `read` / `elicited` / `recall`, because
   `routing._declared_tags` appends `speech_type` to the tag list. `non-lexical` is deliberately
   left unmapped: it covers DDK, glides, breath and cough alike, and forcing only ever *adds* a
   branch, so mapping it to `voice` would run VOICE on every cough file.

Also verified against the shipped files rather than the review's prose: the AudioSet speech family's
display strings use **commas**, not slashes — `"Child speech, kid speaking"` and
`"Narration, monologue"` (YAMNet class map indices 0–3; AST `id2label`).

## Known risks under these guesses

- **HeAR at a 0.5 window threshold will probably read `absent` on genuine airway material.**
  `benchmarks/hear-yamnet.md` retracts the reason for that floor with measurements: over b2ai-28,
  170 spans produced 14 labels at all, the winners span 0.501–0.821, two sit within 0.005 of the
  floor, and *both dedicated cough files got zero labels*. Airway does not go blind — its other
  evidence line reads YAMNet and AST AudioSet labels, one line present and one absent folds to
  `uncertain`, and ROUTING runs a branch on anything not `absent` — but "airway present" will be a
  rarer verdict than the audio warrants. This is the guess most likely to need replacing first.
- **`ambiguous_runs_n` carries no information.** At `voice.f0_range_hz` `[75, 500]` the ratio is
  6.67×, the unflagged band is empty, and 100% of clean phonation flags. Do not triage on it. The
  key that exists to refuse such a configuration at load, `voice.f0_range_ratio_max`, is null
  because nobody has fixed the bound — it is left null rather than invented.
- **`presence_floor` 1 makes "present" a weak claim** on every file, by design, for a screening run.
  Absence still needs both of a kind's lines to read absent, so absence is not made easy.
- **The voice duration cutoffs are a guess over a guess**: they measure phonation spans produced by
  a detector whose own six criterion parameters are themselves unfitted guesses in this file.
- **Release is nondeterministic through recognizer coverage.** v1 saw five files change release
  between two hosts at one commit and one config hash, because which of the two recognizers happens
  to emit a word on non-lexical audio determines whether the verification pass can re-run both
  systems. Expect the same here; it is a property of the fold, not of these guesses.
