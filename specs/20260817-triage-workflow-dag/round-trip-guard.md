# The round-trip guard: what a node writes, and what a reader reads back

`src/tests/audio/workflows/triage/round_trip_guard_test.py`.

## The defect class

Four defects in one day shared one signature: **a reader keyed to something no writer produces,
with a green test because a fixture hand-built the shape instead of exercising the writer.** Each
rendered nothing, on every recording, silently — an absent lane and an unfired flag look exactly
like a recording with nothing to show.

| # | Reader | Keyed to | Written by | Effect |
|---|--------|----------|------------|--------|
| D1 | `verdict._branch_report_from_entity` | did not read `unmeasured` back | `write_report` stored it | `verdict.unmeasured_points_flag` could not fire in the pipeline at all |
| D2 | as above | — | `write_report` stored `in_family` as a constant | survived a 15-mutation run as M12 |
| D3 | `report._airway_labels` | assertion `verb == "label"` generated by node `AIRWAY` | AIRWAY writes no assertion; the only live writer of that verb is SPEECH's PII mark | the airway lane and AIRWAY's branch evidence were blank on every recording ever rendered |
| D4 | `report._spans_of_family(store, "phonation", …)` | span `family == "phonation"` | VOICE mints `family="voice"`, `role="phonation"` | both voice lanes drew nothing, ever |

`hear_span_window` was a fifth of the same shape: a measurement name that existed only in
`report.py` and its own test, and that nothing wrote.

D1 and D2 are one sub-shape (**a writer stores a field its production reader drops or freezes**);
D3, D4 and `hear_span_window` are the other (**a reader selects a value no writer produces**). No
single mechanism catches both cheaply, so the guard is two.

## Why these two mechanisms

Three mechanisms were considered.

A **name registry** — measurement names and span families declared once, writers and readers both
keyed off the declaration — is the strongest, and was rejected as the primary mechanism because it
is a refactor of every writer in the tree for a guard that a sweep gets for free. One half of it was
kept where the declaration already exists: span families come from `branches.BRANCH_FAMILY`, which
is the registry, and the sweep seeds the written set from it rather than inferring it.

A **write→read round trip per writer helper** catches D1 and D2 exactly, and catches D3, D4 and
`hear_span_window` not at all: nothing round-trips, because the reader never matches anything to
begin with. It is the second guard, not the first.

A **static crosswalk** — every literal a reader selects on must be a literal some writer produces —
catches D3, D4 and `hear_span_window`, and cannot see D1 or D2, where both sides agree on the name
and the value is dropped in between.

So: the crosswalk for the selector shape, the round trip for the field shape.

## The crosswalk, and the two ways it was wrong first

The keyed attributes are `name`, `family`, `role`, `verb` — the four an entity scan compares
against.

**The write side deliberately over-collects.** Any expression bound to a parameter or dict key named
after a keyed attribute counts as written, f-strings resolved through the literals their function is
actually called with (`f"{classifier}_window"` in `preprocess._windows`, called with `"yamnet"`,
resolves to `yamnet_window`). Over-collection narrows the guard and can only lose a defect, never
invent one, which is the trade this codebase wants: a guard that cries wolf gets suppressed.

Two failures during construction are worth recording because both produced a *passing* sweep:

1. **Reads self-certifying as writes.** `find_measurement(store, "band_profile")` binds
   `"band_profile"` to a parameter named `name`, so the over-collecting write side counted the read
   as its own justification. Every `name` selection was vacuously satisfied. The fix is
   `_selector_helpers`: a function whose body compares an entity's keyed attribute against one of
   its own parameters is a *reader* helper at that argument, discovered rather than listed, and
   excluded from the write side. `_spans_of_family` is discovered the same way, which is what makes
   D4 visible at all — the selection is an argument to a helper, not a comparison in the lane.
2. **The registry was not inferable.** With reads no longer self-certifying, `family="airway"`
   had no static writer: `PROPOSERS` is built by a dict comprehension over `BRANCH_FAMILY`, and the
   literal never appears at a write site. Inferring it would have meant comprehension-target
   propagation; seeding from `BRANCH_FAMILY` is both shorter and more honest, since that dict *is*
   the declaration.

**Node qualification** is what catches D3, where the value is written — by SPEECH — but not by the
node the reader restricts itself to. A write in `nodes/<x>.py` is attributed to that module's own
`NODE`; a write in a shared module is attributed to every node, because a shared writer writes on
behalf of whoever calls it. A reader function that compares an activity's `node` against a literal
has every selection in it attributed to that node. No such reader exists on the fixed tree, so this
half of the guard is evidenced only by the D3 reintroduction.

## The round trip

`ROUND_TRIP_VALUES` declares two distinguishable values per `BranchReport` field, and
`test_the_table_covers_every_field` fails until a newly added field has a pair — the
conscious-human-checkpoint pattern `revision_pinning_guard_test.py` uses. Both values are asserted,
which is what kills D2: a field frozen to a constant passes one of its two and fails the other.
A dropped field (D1) fails both.

## What it does not cover

- **Attribute *keys*, only values.** A reader reading `span.attributes["onset_kind"]`, which no
  writer stamps, is not seen: the sweep crosswalks the value of a keying attribute, not the presence
  of a payload key.
- **Values built at runtime on the read side.** `find_measurement(store, f"{classifier}_scores")`
  contributes no literal, so it is neither checked nor able to fail. The write side resolves
  f-strings; the read side deliberately does not, because resolving them there would manufacture
  selections nobody makes.
- **Round-trip beyond `BranchReport`.** `write_verdict`, `propose_span`, `write_findings`, the `pii`
  and `redaction_llm_annotation` writers have no field-driven round trip. `write_verdict`'s payload
  is not read back into a dataclass by any node — `NodeVerdict` is constructed at the fold — so
  there is no production reader to round-trip against; the others carry open-ended `**attributes`,
  where "every field survives" has no closed set to quantify over.
- **Whether a reader that matches something matches the *right* thing.** A lane selecting a written
  family that is nevertheless the wrong family renders, so the guard is satisfied.
- **Everything outside `senselab/audio/workflows/triage/`.**

## The allowlist

One entry, `("name", "band_profile")`, and the reason is in the code beside it:
`airway.content_band_hz` reads a roll-off no node computes, and says so in its own docstring.
`test_every_exemption_is_still_needed` fails the entry out when the reader goes away or a writer
appears.
